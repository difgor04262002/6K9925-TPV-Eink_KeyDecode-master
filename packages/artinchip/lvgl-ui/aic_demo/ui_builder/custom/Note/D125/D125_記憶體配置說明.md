# D125 記憶體配置詳細說明

> 適用平台：D125 / SDK 晶片名 **D12P**（`CONFIG_PRJ_CHIP="d12p"`）
> 適用板卡：`demo88-nor`
> 適用面板：ZC-T1D8BP-012（`CONFIG_AIC_PANEL_DBI_ZC_T1D8BP=y`），360 × 360、QSPI / ST77916
> 核心 / 應用：RT-Thread + `helloworld` + LVGL v9 UI Builder
> 方案 defconfig：`target/configs/d12p_demo88-nor_rt-thread_helloworld_zc_t1d8bp_defconfig`
>
> **不要拿 `DDR_圖片顯示記憶體使用說明.md`（D215、64 MB DRAM、800×800）直接套這顆。**
> D125 是 **16 MB PSRAM**，不是 DRAM；CMA / 系統 heap 的切法也相反（韌體先佔 CMA，系統 heap 在末端 2 MB）。
>
> 數字以 `output/d12p_demo88-nor_rt-thread_helloworld_zc_t1d8bp/images/`（2026-09-10）為準：`.img` **9 124 352 B（8.70 MiB）** 是燒錄包；進 PSRAM 的程式到 `__bss_end__ = 0x401739F4`（**1 522 164 B ≈ 1.45 MB**）。見 §4.1。

本文件整理目前方案的物理 layout、兩個 heap、NOR 分區、**.img 與 RAM 的差別**、圖片 / 串流路徑上的 buffer，以及已知瓶頸。配合 `custom_Image_流程說明.md`、`USB_Composite_Display功能與修改歷程.md` 一起看會更完整。

## 1. 晶片上有哪些記憶體

| 區塊 | 基址 | 大小 | 設定來源 | 用途 |
|------|------|------|----------|------|
| BROM | `0x30000000` | 32 KB | linker 固定 | Boot ROM |
| SRAM | `0x30040000` | **20 KB**（`0x5000`） | `CONFIG_AIC_SRAM_SIZE` 預設 | 全給 VE / SRAM_CMA |
| PSRAM | `0x40000000` | **16 MB**（`0x1000000`） | `CONFIG_AIC_PSRAM_SIZE` | 韌體 + CMA + 系統 heap |

Heap 註冊：`target/d12p/demo88-nor/board.c` 的 `aic_memheap_init()` / `rt_system_heap_init()`

## 2. PSRAM 物理布局（16 MB）

Linker 把 16 MB 切成兩段（**不是** D215 那種「低 16 MB 系統 + 高 48 MB CMA」）：

```
0x40000000 ┬─────────────────────────────────────────┐ ← __psram_start / ITB load
           │  .text / .rodata / .data / .bss          │
           │  到 __bss_end__ = 0x401739F4             │  1 522 164 B（1.45 MB）
           │  （d12p.map，2026-09-10 這次編譯）        │
           ├─────────────────────────────────────────┤ ← __cma_heap_start
           │  heap_cma  (MEM_CMA)                     │  13 059 596 B（12.46 MB）
           │  → 0x40E00000                            │  PSRAM_CMA 剩餘
           │  DMA / VE / GE / QSPI / USB 圖 buffer    │
           │                                          │
0x40E00000 ┼─────────────────────────────────────────┤ ← __heap_start
           │  System Heap (MEM_DEFAULT)               │    2 MB 整
           │  → 0x41000000                            │  PSRAM_SW
           │  malloc / LVGL 物件 / jpgdec bounce      │
           │                                          │
0x41000000 ┴─────────────────────────────────────────┘ ← __psram_end
```

設定來源：

| 項目 | 來源 | 值 |
|------|------|-----|
| PSRAM 總量 | defconfig `CONFIG_AIC_PSRAM_SIZE` | `0x1000000`（16 MB） |
| 系統 heap 保留 | defconfig `CONFIG_AIC_PSRAM_SW_SIZE` | `0x200000`（2 MB） |
| CMA 區段長度 | `AIC_PSRAM_SIZE - AIC_PSRAM_SW_SIZE` | **14 MB** |
| CMA 區段範圍 | linker `PSRAM_CMA` | `0x40000000` … `0x40E00000` |
| 系統 heap 範圍 | linker `PSRAM_SW` | `0x40E00000` … `0x41000000` |
| 韌體放哪 | `REGION_TEXT/RODATA/DATA/BSS` → `PSRAM_CMA` | 從 `0x40000000` 往上長 |
| CMA heap 起點 | `d12p.map` `__cma_heap_start` | **`0x401739F4`**（`.bss` 之後） |
| CMA heap 長度 | `0x40E00000 − 0x401739F4` | **13 059 596 B（12.46 MB）** |
| 中斷堆疊 | `CONFIG_AIC_INTERRUPTSTACK_SIZE` | **4096**，在 `.bss` 內 |
| 量測來源 | `output/d12p_demo88-nor_rt-thread_helloworld_zc_t1d8bp/images/` | `d12p.map` / `d12p.summary.csv` / `d12p_os.its` |

`d12p.summary.csv` 各段（同一編譯）：

| Section | Size |
|---------|------|
| `.text` | 1 067 440 |
| `.eh_frame` | 6 016 |
| `.rodata` | 216 704 |
| `.data` | 13 748 |
| `.bss` | 218 228 |
| 合計（含對齊） | **1 522 711** |

寫進 `d12p.bin` / `seg0.bin` 的是前四段（**1 303 924 B**）；`.bss` 218 KB 不佔 Flash，但開機後在 PSRAM 清零，所以 **RAM 常駐 = 檔案 1.24 MB + .bss ≈ 1.45 MB**。`d12p_os.its`：`load = entry = 0x40000000`。

### 兩個 heap 的差異

| 區別 | System Heap（PSRAM_SW） | CMA Heap（PSRAM_CMA 剩餘） |
|------|-------------------------|----------------------------|
| 物理位置 | 末端 **2 MB** | 前端 14 MB 減去韌體 |
| 是否 contiguous | 不保證 | **保證 contiguous** |
| 對 DMA 是否友善 | 通用 | 需 `CACHE_LINE_SIZE` 對齊 + dcache clean/invalid |
| 配置 API | `malloc` / `rt_malloc` / `lv_malloc` / `aicos_malloc(MEM_DEFAULT, …)` | `aicos_malloc(MEM_CMA, …)`、`aicos_malloc_align(MEM_CMA, …)`、`aicos_malloc_try_cma()` |
| 主要使用者 | LVGL object / style、jpgdec `s_job_buf`、一般 C 堆、執行緒控制塊 | USB 圖 recv/ready、Area4 顯示緩衝、QSPI tx / splash、MPP bitstream + frame、LVGL image cache、draw buf |
| HW 可否直接 DMA | ❌ | ✅（CMA 設計目的） |

D12P 的 `board.c` **不**把 SRAM 註冊成獨立 memheap（`#ifndef AIC_CHIP_D12P` 包住 SRAM heap）。20 KB SRAM 留給 VE，不是給 `malloc` 用。

## 4. NOR Flash 16 MB 分區

來源：`target/d12p/demo88-nor/pack/image_cfg.json`

| 分區 | 大小 | 約略偏移 | 內容 |
|------|------|----------|------|
| spl | 512 KB | `0x000000` | bootloader.aic |
| env | 128 KB | `0x080000` | U-Boot env |
| env_r | 128 KB | `0x0A0000` | env 冗餘 |
| userid | 256 KB | `0x0C0000` | 至少 16 KB 保留 |
| os | **3 MB** | `0x100000` | `d12p_os.itb` |
| rodata | **10 MB** | `0x400000` | FAT（`rodata.fatfs`） |
| data | **2 MB** | `0xE00000` | LittleFS（`data.lfs`） |
| **合計** | **16 MB** | | |

這是 **Flash 儲存**，不是執行 RAM。開機後只有 **os 分區**被載進 PSRAM 前端執行；`rodata` / `data` 留在 NOR，用檔案系統 mount 上來讀。

### 4.1 為何 `d12p_demo88-nor_v1.0.0.img` 將近 9 MB，RAM 怎麼配

來源目錄：`output/d12p_demo88-nor_rt-thread_helloworld_zc_t1d8bp/images/`（2026-09-10）。  
Explorer 的 8.7 MB `.img` 容易讓人以為「韌體 9 MB、PSRAM 只剩 7 MB」。**不是這樣。**

`.img` 是 `mk_image.py` 的**燒錄容器**（Header + Meta + 各元件檔）。同一目錄實際位元組：

| 檔案 | 位元組 | MiB | 是什麼 | 進 PSRAM？ |
|------|--------|-----|--------|-----------|
| `d12p_demo88-nor_v1.0.0.img` | **9 124 352** | 8.70 | 燒錄包 | ❌ |
| `rodata.fatfs` | **6 172 672** | 5.89 | UI FAT（分區上限 10 MB） | ❌ NOR |
| `rodata.fatfs.sparse` | 6 112 956 | 5.83 | 同一份 FAT 的 sparse | ❌ |
| `data.lfs` | **1 048 576** | 1.00 | LittleFS（2026-09-10 快照為 1 MB；現分區 **2 MB**） | ❌ NOR |
| **`d12p_os.itb`** | **1 306 624** | 1.25 | OS FIT（分區上限 3 MB） | ✅ `load=0x40000000` |
| `d12p.bin` / `seg0.bin` | **1 303 924** | 1.24 | itb 裡的 raw 程式 | ✅ 再加 `.bss` |
| `d12p.elf` | 13 091 660 | 12.48 | 含 debug，**不燒錄** | ❌ 只在 PC |
| `d12p.map` | 4 554 202 | 4.34 | 連結對照 | ❌ |
| `bootloader.aic` | 281 616 | 0.27 | `.img` 裝 **兩份**（updater + spl） | ❌ 暫載 |
| `bootloader.bin` | 265 264 | 0.25 | bootloader 本體 | ❌ |
| `usbupg-psram-init.aic` | 16 144 | 0.02 | USB 燒錄時初始化 PSRAM | ❌ 暫載 |
| `env.bin` | 4 096 | — | env / env_r 各一份 | ❌ |

`.img` 怎麼加到 9 124 352（約略）：

```
rodata.fatfs              6 172 672
data.lfs                  1 048 576
d12p_os.itb               1 306 624
bootloader.aic × 2          563 232
usbupg-psram-init.aic        16 144
env.bin × 2                   8 192
Header + Meta + 對齊         ≈ 8 912
────────────────────────────
d12p_demo88-nor_v1.0.0.img  9 124 352
```

**不要用 `d12p.elf` 的 12.48 MB 算 RAM。**

RAM 只扣 OS 程式（`d12p.map`）：

```
16 MB PSRAM（本編譯）
0x40000000 ┬──────────────────────────────────────────┐
           │  .text 1 067 440                         │
           │  .rodata 216 704 + .data 13 748 + …      │  bin 1 303 924
           │  .bss 218 228                            │  不在 Flash，在 RAM
           │  __bss_end__ / __cma_heap_start          │
0x401739F4 ├──────────────────────────────────────────┤  常駐 1 522 164（1.45 MB）
           │  CMA heap                                │  13 059 596（12.46 MB）
0x40E00000 ├──────────────────────────────────────────┤
           │  系統 heap（malloc）                      │   2 097 152（2.00 MB）
0x41000000 ┴──────────────────────────────────────────┘
```

**Heap** = 用時再要、用完可還的池子。系統 heap = `malloc`；CMA heap = DMA。都在 PSRAM，跟 8.70 MiB `.img`、5.89 MiB FAT 無關。

板上 `meminfo` 的 `heap_cma` total 應對準 **≈ 12.46 MB**（對齊後可能差幾 KB），不該是 `16 − 8.7`。

## 5. 顯示相關常數

| 項目 | 值 | 來源 |
|------|-----|------|
| 邏輯解析度 | 360 × 360 | `custom_disp_profile.h`（`AIC_PANEL_DBI_ZC_T1D8BP`） |
| Profile 巨集 | `CUSTOM_DISP_IS_ROUND_PROFILE=1` | 同上 |
| Framebuffer 像素格式 | RGB565 | `CONFIG_AICFB_RGB565=y` |

## 6. CMA 上的常駐大緩衝

> 目的：壓縮圖 byte 流、解碼 frame、QSPI DMA、GE/VE。
> 幾乎全部 `aicos_malloc_align(MEM_CMA, …)` 或 MPP 內部從 CMA 配。

| Buffer | 大小 | 檔案 | 生命週期 |
|--------|------|------|----------|
| `s_recv_buf` | **1 MB** | `custom_Image.c` `CUSTOM_IMAGE_BUFFER_SIZE` | init 預配，swap 只換指標 |
| `s_ready_buf` | **1 MB** | 同上 | 同上 |
| `s_area4_disp_buf` | **1 MB** | `custom_Area4.c` `CUSTOM_AREA4_BUF_SIZE` | init 預配 |
| QSPI `tx_buf`（`tx_pp[0]`） | **388800** | `lv_aic_spi.c` | 開顯示後常駐 |
| QSPI `tx_pp[1]` | **388800** | 同上 ping-pong | 常駐（配不到就單緩衝） |
| `splash_keep` | **388800** | `lv_aic_spi.c` | 第一次 splash 後複製一份 |
| LVGL draw `buf1` / `buf2` | 各 **259200**（RGB565） | `lv_spi_display_init()` | 常駐；`stream_buf[0/1]` 共用 |
| MPP JPEG bitstream | **1 MB** | `custom_disp_stream.c` `CUSTOM_STREAM_BITSTREAM_BUF_SIZE` | decoder init |
| MPP frame ×2（`extra_frame_num=1`） | 360×360 RGB565 ≈ 各 **259 KB**；VE 常 pad 到 368 寬 | MPP 內部 | decoder 存活期間 |
| LVGL image cache | **2 MB** | `LV_CACHE_DEF_SIZE` | LVGL 啟動後 reserve |
| USB vender OUT `read_buffer` | **128 KB** | `usbd_vender_template.c` `VENDER_OUT_READ_BUF_LEN` | `.noncacheable` 靜態 |
| USB vender IN `write_buffer` | **2 KB** | 同上 | 靜態 |
| GE2D CMDQ | **2 KB** | GE 驅動 | 開 GE 後 |
| `s_h0499_splash_snap` | 視 draw buf | `custom.c` `aicos_malloc_try_cma` | splash 擷取時；本面板可能走 round splash，不一定配到 |

粗估常駐（360×360、雙 tx、雙 draw、雙 MPP frame、cache 滿配）：

```
1 + 1 + 1                    =  3.00 MB   recv / ready / area4
0.37 + 0.37 + 0.37           =  1.11 MB   tx ping-pong + splash_keep
0.25 + 0.25                  =  0.50 MB   LVGL draw ×2
1.00                         =  1.00 MB   bitstream
0.25 + 0.25                  =  0.50 MB   MPP frame ×2（最小；對齊後更多）
2.00                         =  2.00 MB   LVGL cache
0.13                         =  0.13 MB   USB OUT
────────────────────────────────────────
合計約                         ≈  8.2 MB
```

再加上韌體映像本體（在同一 14 MB CMA 前段），CMA 剩餘可能只剩 **數 MB**。這就是註解寫「須省給 VE/QSPI」的原因。

若 PC 送來的 JPEG 解成接近 1024×600 RGB565，單 frame ≈ 1.2 MB，兩槽可到 **~2.4 MB**，CMA 會明顯變緊。

任何 USB 圖 **> 1 MB** 會被 `custom_Image` 直接 reject。

## 7. 系統 heap（2 MB）上的配置

> 目的：一般 malloc、LVGL 物件樹、jpgdec bounce。
> HW **不會**直接 DMA 進這裡。

| Buffer / 用途 | 大小 | 分配 | 備註 |
|---------------|------|------|------|
| `s_job_buf` | **48 KB** | `aicos_malloc(MEM_DEFAULT, CUSTOM_STREAM_JOB_MAX)` | USB JPEG 先拷這裡再交給 `jpgdec` |
| LVGL objects / styles / event | 數百 KB～數 MB（視畫面） | `lv_malloc` → 系統 heap | 圓屏 UI 比 1280×800 小很多 |
| RT-Thread 執行緒 TCB + 動態 stack | 見 §8 | kernel | 部分 stack 是靜態陣列（在 `.bss` / CMA） |
| 其餘 `malloc` | 動態 | — | 避免在這條 path 再動態長出 MB 級緩衝 |

### 已知瓶頸：`CUSTOM_STREAM_JOB_MAX = 48 KB`

`custom_disp_stream.c` 把 decode 從 LVGL 10 ms tick 挪到 `jpgdec` worker，避免 VE wait（最長 2 s）卡住 USB heartbeat。bounce 目前只有 48 KB。

實機 JPEG 常 **140–155 KB**，會印：

```text
job drop, jpeg N > 49152
```

MPP bitstream 本身有 **1 MB**，卡點是這塊系統 heap bounce，不是 CMA。若要收 live JPEG，應把 `CUSTOM_STREAM_JOB_MAX` 拉到至少 256 KB（仍遠小於 2 MB 系統 heap）。**目前刻意暫不調整。**

## 8. 執行緒堆疊

| 執行緒 | Stack | 來源 |
|--------|--------|------|
| LVGL 主執行緒 | **48 KB** | `CONFIG_LPKG_LVGL_THREAD_STACK_SIZE=49152`（靜態陣列，在 `.bss`） |
| `jpgdec` | **8 KB** | `aicos_thread_create("jpgdec", 8192, …)` |
| main | **8 KB** | `CONFIG_RT_MAIN_THREAD_STACK_SIZE=8192` |
| MMCSD | **8 KB** | `CONFIG_RT_MMCSD_STACK_SIZE=8192` |
| `custom_uart_rx` | **2 KB** | `CUSTOM_UART_THREAD_STACK_SIZE` |
| idle | **1 KB** | `CONFIG_IDLE_THREAD_STACK_SIZE=1024` |
| IRQ / interrupt stack | **4 KB** | `CONFIG_AIC_INTERRUPTSTACK_SIZE=4096` |

靜態 stack（LVGL 48 KB 等）吃的是 **PSRAM_CMA 的 `.bss`**，會再縮小 CMA heap，不是從 2 MB 系統 heap 扣。

## 9. 一張 USB JPEG 在記憶體裡怎麼走

圓屏串流（`CUSTOM_DISP_IS_ROUND_PROFILE`）：

```
PC USB bulk
    │
    ▼
read_buffer  128 KB（.noncacheable）
    │  custom_image_feed()
    ▼
s_recv_buf   1 MB CMA  ──swap──►  s_ready_buf  1 MB CMA
    │
    ▼  tick pickup
s_job_buf    48 KB 系統 heap     ← 超過 48 KB 在這裡 drop
    │  jpgdec worker
    ▼
MPP bitstream  1 MB CMA
    │  VE decode
    ▼
MPP frame ×2   ~259 KB+ CMA（VE 可能 pad 寬到 368）
    │  CPU crop-copy（custom_stream_blit_to_spi）
    ▼
LVGL / SPI draw buf   259 KB CMA
    │  GE 或直接組 tx
    ▼
QSPI tx_buf / tx_pp   389 KB CMA  ──DMA──►  面板
```

非串流、Area4 widget 路徑則 `s_ready_buf` → `s_area4_disp_buf`（1 MB CMA）→ LVGL decoder / cache（2 MB）。

## 10. 和 D215 文件的對照（避免套錯）

| 項目 | D215（舊文件） | **本 D125 方案** |
|------|----------------|------------------|
| 記憶體種類 | 64 MB DRAM | **16 MB PSRAM** |
| 系統 heap | 低段 ~16 MB（扣韌體後 ~14 MB） | **末端固定 2 MB** |
| CMA | 高段 48 MB | **前端 14 MB 扣韌體**（本編譯可用 **12.46 MB**） |
| 面板 | 800×800 ARGB8888 MIPI | **360×360 RGB565 QSPI** |
| 單幀未壓縮 | 2.56 MB（ARGB） | **0.25 MB**（RGB565）或 0.37 MB（RGB666 tx） |
| USB recv/ready | 各 1 MB CMA | 相同策略，但 CMA 更緊 |
| LVGL cache | 2 MB（從 8 MB 砍下來） | **同為 2 MB** |
| 4 MB YUV 中間緩衝 | 曾考慮 / 後停用 | **未配** |
| 串流 bounce | 無此 48 KB 限制 | **`s_job_buf` 48 KB，live JPEG 會 drop** |

## 11. 改配置時改哪裡

| 想改什麼 | 改哪個檔 / 哪個巨集 |

| jpgdec bounce（live JPEG drop） | `CUSTOM_STREAM_JOB_MAX` |
| LVGL cache | defconfig `CONFIG_LV_CACHE_DEF_SIZE` / `CONFIG_LV_CACHE_IMG_NUM` |
| JPEG 最大輸出 | `CONFIG_MPP_JPEG_DEC_MAX_OUT_WIDTH/HEIGHT` |
| LVGL / main / idle stack | defconfig 對應 `*_STACK_SIZE` |

加大任何 CMA 常駐緩衝前，先估 §6 合計 + 韌體，確認 14 MB 前端還剩多少。系統 heap 只有 2 MB，不要把 MB 級 buffer 搬回去 `malloc`。

## 12. 實機怎麼核對

開機後 serial 115200 8N1，shell：

```text
meminfo
```

應能看到 `heap`（系統 2 MB）與 `heap_cma`（CMA 剩餘）的 total / used / max / avail。

編譯產物目錄：

```text
output/d12p_demo88-nor_rt-thread_helloworld_zc_t1d8bp/images/
```

先看 **`d12p_os.itb` / `d12p.bin`**，不要用 `.img` 去減 PSRAM。本編譯 map 已量過：`__bss_end__ = 0x401739F4`、`__cma_heap_start` 同址、`__heap_start = 0x40E00000`（見 §2、§4.1）。

Area4 路徑每隔一段會打 `heap snapshot: sys total=… used=…`（系統 heap）；CMA 仍以 `meminfo` 為準。
